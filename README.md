# ChatUI

A fully local, privacy-first knowledge assistant built on top of your Obsidian vault. It combines vector-based semantic search, locally-running LLMs via Ollama, and an optional DuckDuckGo web fallback — all inside a terminal UI. Every function is accessible as a `/command` within the chat.

---

## Usage

```bash
python chatui.py
```

No flags needed. On first launch, type `/ingest` to build the vector database from your vault.

---

## Commands

| Command | Description |
|---|---|
| `/help` | List all available commands |
| `/browse` | Open a TUI file browser to load any vault file as context |
| `/ingest` | Rebuild the vector database from vault markdown files |
| `/organize` | Add YAML frontmatter tags and `[[wikilinks]]` to vault notes |
| `/savefile` | Review and save pending notes to the vault |
| `/clear` | Reset conversation history and unload any open file |
| `/web` | Toggle the DuckDuckGo web search fallback on / off |
| `/update` | Apply `CHANGE:`/`REMOVE:`/`RENAME:`/`FIX:` directives from config files |
| `/apply` | Write the changes proposed by `/update` (yes/no confirmation, atomic write) |
| `/version` | Print the current chatui.py version string |

**Keyboard shortcuts**

| Key | Action |
|---|---|
| `Ctrl+S` | Shortcut for `/savefile` |
| `Ctrl+B` | Shortcut for `/browse` |
| `Ctrl+Q` | Quit |
| `Esc` | Clear the input field |

## Self-updating via config

chatui can modify its own code from plain-English directives in `config/settings.md`. Add a directive, run `/update`, review the diff, `/apply`, restart.

**Directive prefixes:**

| Prefix | Effect |
|---|---|
| `CHANGE: add /X …` | Add new command X (handler + method body + help line) |
| `REMOVE: /X command` | Remove command X and its method |
| `RENAME: /X → /Y` | Rename command X to Y everywhere |
| `FIX: description` | Targeted bug fix — model identifies and patches the relevant method |

**How it works:**
1. `git diff` against `.chatui_sync` finds changed config lines since the last `/apply`
2. Directives are extracted from added lines
3. Handler entries and help lines are inserted deterministically; method bodies are generated by `qwen2.5-coder:7b` with a focused ~60-line context window
4. The assembled source is validated with `ast.parse` + `py_compile` before you see it — bad generated code falls back to a working stub
5. `/apply` writes atomically (`os.replace`) and advances `.chatui_sync` to HEAD

## Configuration

All settings live in `config/` as self-documenting markdown files with YAML frontmatter.

| File | Controls |
|---|---|
| `config/models.md` | Model role assignments; `models:` list is auto-pulled on launch |
| `config/settings.md` | Thresholds, chunk sizes, history window, vault path — also where you write directives for `/update` |

## Setup

```bash
# Install dependencies
pip install langchain langchain-ollama langchain-community chromadb \
            duckduckgo-search textual pyyaml

# Models are pulled automatically on first launch from config/models.md.
# To pull manually:
ollama pull nomic-embed-text
ollama pull llama3.2:3b
ollama pull qwen2.5-coder:7b

# Run
python chatui.py
# Then type /ingest to build the database on first launch
```

## Suggested prompts

These show what chatui can do once your vault is ingested.

**Vault retrieval**
```
What have I written about machine learning?
Summarise my notes on photosynthesis
What's the difference between supervised and unsupervised learning based on my notes?
```

**With a file open (`/browse` first)**
```
/browse
# select kinematics.md
Explain the key equations in this note in plain English
What prerequisites would I need to understand this properly?
```

**Learning and saving**
```
Explain backpropagation
# if the answer is good, Ctrl+S → review note → save it to the vault
What is gradient descent and why does it matter?
```

**Web search fallback**
```
/web
What are the latest developments in local LLMs?
# uncertain answers automatically trigger a DuckDuckGo search for more context
```

**Vault organisation**
```
/organize
# walks through every note suggesting tags and [[wikilinks]] interactively
```

**Self-update workflow**
```
# 1. Add to config/settings.md:
#    CHANGE: add a /stats command that shows vault chunk count and DB size
# 2. Commit the change (or leave it uncommitted)
# 3. In chatui:
/update
/apply
# restart, then:
/stats
```

## Suggested improvements

- **Re-ingest on change** — watch the vault with `watchdog` and automatically re-embed modified files
- **Smarter chunking** — chunk by markdown heading rather than character count so each chunk stays semantically coherent
- **Note deduplication** — before saving, check if a semantically similar entry already exists and offer to append instead
- **Multi-vault support** — accept `vault_path` as a CLI argument, overriding `config/settings.md`
