# Fine-Tuning Reference

Fine-tuning adapts a pretrained model to a specific task or domain by continuing training on a curated dataset. The pretrained base already has language understanding; fine-tuning teaches it behaviour (follow instructions, adopt a style, learn domain facts).

## The Fine-Tuning Spectrum

### Full Fine-Tuning
Update every parameter. Most flexible, highest quality ceiling, but requires as much VRAM as initial pretraining and risks catastrophic forgetting of base capabilities.

### PEFT (Parameter-Efficient Fine-Tuning)
Umbrella term for methods that keep base weights mostly frozen and train only a small set of additional or selected parameters.

| Method | Mechanism | Trainable % |
|---|---|---|
| **LoRA** | Low-rank adapter matrices injected into weight projections | 0.1–1% |
| **QLoRA** | LoRA on a 4-bit quantised base model | 0.1–1% |
| **Prefix tuning** | Trainable prefix tokens prepended to every layer | <0.1% |
| **Adapter layers** | Small bottleneck MLP inserted between transformer sublayers | 0.5–3% |
| **IA³** | Learned vectors that scale and shift attention and FFN activations | <0.1% |

LoRA and QLoRA dominate practical use because they have no inference latency overhead (adapters merge into weights after training).

### Supervised Fine-Tuning (SFT)
Training on (instruction, response) pairs written by humans or generated by a stronger model. This is the first stage of RLHF. Teaches the model the response format and basic instruction-following before preference learning.

### Continued Pretraining
Run more self-supervised next-token prediction on a domain corpus (medical papers, code, legal text). Injects domain knowledge into the base weights. Typically followed by SFT or LoRA for instruction-following.

## When to Use Which

- **Domain knowledge injection** → Continued pretraining + LoRA
- **Instruction-following / chat** → SFT on (prompt, response) pairs
- **Preference alignment** → DPO or RLHF after SFT
- **Resource constraint (consumer GPU)** → QLoRA
- **Task specialisation, minimal VRAM** → LoRA r=8–16

## Common Pitfalls

- **Catastrophic forgetting** — full fine-tuning can overwrite base capabilities. LoRA avoids this by keeping W frozen.
- **Overfitting on small datasets** — fine-tuning on <1k examples usually needs regularisation or very low rank.
- **Data format mismatch** — the training prompt format must exactly match the inference format (chat templates, special tokens).
- **Learning rate too high** — fine-tuning typically uses 10–100× lower LR than pretraining.
